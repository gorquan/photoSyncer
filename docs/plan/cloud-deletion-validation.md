# 云端删除同步的证据与验证范围

> 当前能力：小米全量/时间线保留完整清单及回收站删除检查，小米位点仅备份；iCloud 镜像改为按位点处理删除。下文完整扫描流程仅适用于小米及 iCloud 基线阶段。真实 Apple 删除/恢复场景尚未通过破坏性云端实测；合成协议、SQLite 与文件测试不能替代这一结论。

## 删除依据

开启 `syncCloudDeletes` 的任务先完整检查所选相册，再确认本地已知但未在本轮观察到的逻辑照片。相册成员关系与图库删除分开判断，全部检测成功后才提交删除状态。

2026-10-17 使用已授权账号进行只读核对：小米 `/gallery/deleted_v2?maxTag=0&limit=50` 返回 18 条现有回收站记录，`id`、`syncTag` 为字符串，`deleteTime` 为正整数，`lastPage` 为布尔值。查询其中一条已删除记录的存储接口返回业务码 50050，说明为非法状态。因此不能把 50050 独立当成删除证明。响应中的账号和媒体标识留在仓库外，文档与测试不包含个人媒体或认证材料。

iCloud 通过当前图库的完整单记录 `records/lookup` 确认：明确删除标志或对应记录的 `NOT_FOUND` / `UNKNOWN_ITEM` 才证明删除。只读查询该测试账号的最近删除集合未取得已删除样本；删除响应由本地协议测试覆盖。没有为测试删除真实云端照片。

小米若在首次观察删除前已永久清空回收站，现有证据可能无法区分永久删除与不可访问。此时检测失败并保留文件。此前已持久化确认的删除状态可继续本地重试；新的有效云端观察可以恢复照片状态。

## 自动化断言

- 协议与数据库测试：完整分页、明确删除、相册移出和隐藏/收藏变化、认证或分页错误、账号隔离、所有成员关系和来源版本、恢复，以及已确认删除后回收站清空的重试。
- 文件清理测试：Apple 图片/配套视频/alternate、小米单文件、历史原件、准备失败留下的原件、缺失文件、部分 unlink 后重试、外部修改、未托管文件、符号链接、越界路径、共享引用和恢复后再次删除。
- 并发测试：发布与清理共享逻辑照片锁；已经排队的旧发布任务在获得锁后重新检查数据库，不能从留存原件重建已删除照片。
- API 端到端测试使用合成小米云数据执行删除和恢复，验证本地导出、原件库和公开历史状态。iCloud 删除以协议测试及 SQLite/临时文件集成验证为依据，不等同于真实 Apple 云端删除实测。

## 完成状态的含义

清理记录区分本次实际删除的导出文件数、原件数、共享引用暂缓、文件冲突及失败。删除前先持久化日志；多个文件的删除可恢复，但不是一个原子操作。进程中断时保留重试依据，不能用任务结束时间推断全部清理成功。

API 与 MCP 的 `executionStatus` 区分运行中、成功、部分完成、失败和取消；`deletionReport` 保存删除检查计数、每个逻辑照片组的清理结果、实际文件计数及安全错误说明。删除清理已完成但后续发布失败时，删除报告继续保留已完成证据，执行结果单独标为失败。界面使用同一生成类型展示，分组历史保留删除报告和未成功执行。

本地导出消失后，群晖 Photos 依靠正常文件索引移除项目。此功能不修改群晖数据库、不操作 `@eaDir`，也不保证索引延迟。此前媒体配对、原始字节及 NAS 动态播放验证见 [群晖兼容验证](synology-photos-validation.md)。

## 验证结果（2026-10-17）

- 后端 28 套件、194 项单元测试通过；完整 JVM API 端到端流程通过，新增全量/时间线/位点增量三种模式的删除、重复同步、恢复、再次删除、修改冲突及修复重试，还断言删除检测失败时不推进普通刷新和位点、不清理或发布文件。
- Go 模拟服务测试、前端 lint/format/build（含 TypeScript 和中英文词条检查）、干净 `compileKotlin` 与 `solonJar` 构建、差异格式检查通过。原生反射 JSON 检查通过，但未构建或执行原生可执行文件。
- 使用隔离的本地数据库与文件目录，在两个禁用定时运行的真实账号测试任务中开启删除同步，分别检查 Apple 6 个逻辑照片组（12 个资源）及小米 11 个资源。两次执行均为 `SUCCESS`，删除报告均为 `COMPLETE`，新增删除和实际文件删除计数均为零。
- 独立比较运行前后的 23 个导出文件和 23 个原件：没有缺失文件、没有内容哈希变化，原件修改时间全部保持不变；数据库没有被标记删除的资源。账号仅执行读取和正常同步，没有删除真实云端媒体。验证实例运行于回环地址，完成后已关闭，原有基线实例未变更。

这些实测证明当前有效云端样本在开启删除检查后保持完整。真实云端删除的破坏性场景使用合成数据验证；没有据此声称真实 Apple 删除事件或 NAS 删除索引时延已实测。
